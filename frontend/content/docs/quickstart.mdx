## Requirements

Python 3.11 or newer and Git. The runtime core deliberately stays light —
`cryptography` for Ed25519 and `PyYAML` for configuration — because a
coordination substrate that drags in a message broker is harder to trust and
harder to reproduce.

```bash
git clone https://github.com/Sagexd08/CausalMesh
cd CausalMesh
pip install -e ".[dev]"
```

## Run the test suite

```bash
pytest                    # 1,148 tests
pytest -m "not slow"      # skips the integration tests that spawn subprocesses
```

The slow tests execute real runs: real workspaces, real agents, real
`pytest` subprocesses inside those workspaces. They take minutes because
they are doing the thing rather than asserting about it.

## Execute a collection

```bash
causalmesh doctor                           # is this environment able to run?
causalmesh task validate                    # is the task suite well-formed?
causalmesh experiment plan --profile smoke  # what would run, without running it
causalmesh experiment run  --profile smoke  # 1 task x 4 arms x 1 repetition
causalmesh experiment status --latest       # per-arm successes, denials, bytes
causalmesh analyze --latest                 # costs and the four contrasts
causalmesh manifest write --latest          # record what the collection produced
causalmesh audit --latest                   # evidence present, unchanged, valid
```

`run` is resumable and idempotent: progress lives in the run index, not in
the process, so a second invocation continues rather than restarts. Every
command takes `--json`, and exit codes carry meaning — `0` success, `1` a
negative result, `2` a bad invocation, `3` could not run.

<Callout title="A failed run is evidence">
`experiment run` exits `0` even when runs fail their task. C0 is *expected*
to fail; a collection that refused to record that would be measuring
nothing. Only an incomplete collection exits non-zero.
</Callout>

### The same thing from Python

The CLI is a wrapper. Anything it does is reachable directly, which is what
you want when a collection is one step inside a larger script:

```python title="run_smoke.py"
import asyncio
from pathlib import Path

from causalmesh.experiments import plan_experiment, profile
from causalmesh.scheduler import ExperimentRunner, RunEnvironment
from causalmesh.tasks import TaskDefinition

SEED = b"a-seed-you-record-somewhere"

async def main():
    task = TaskDefinition.from_yaml("tasks/schema_handler_widen.yaml")

    plan = plan_experiment(
        experiment_id="my_first_run",
        profile=profile("smoke"),          # 1 task x 4 arms x 1 repetition
        task_ids=[task.task_id],
        master_seed=SEED,
        task_hashes={task.task_id: task.content_hash()},
    )

    environment = RunEnvironment.under(".", experiment_id="my_first_run")

    with ExperimentRunner(
        plan=plan,
        tasks={task.task_id: task},
        environment=environment,
        master_seed=SEED,
    ) as runner:
        runner.prepare()
        report = await runner.run()
        print(report.summary())

asyncio.run(main())
```

```bash
python run_smoke.py
```

<Callout title="The seed is not optional">
`master_seed` is a required argument with no default. A run whose seed
nobody recorded cannot be reproduced, and the API refuses to let that happen
quietly. Everything derived from it — signing keys, execution order,
per-run seeds — comes from HMAC over that value.
</Callout>

## Read what it produced

```
data/raw/my_first_run/
  index.db                        operational run index (resumable)
  my_first_run__..._C0__r0000/
    run.json                      chain + outcome + coordination accounting
  my_first_run__..._C1__r0000/
  my_first_run__..._C2__r0000/
  my_first_run__..._C3__r0000/
```

A smoke collection answers only "does the machinery run end to end". With
one repetition per cell it estimates nothing, and the profile's own
docstring says so.

## Verify a chain offline

```bash
causalmesh verify --id my_first_run         # every run in one collection
causalmesh verify --all                     # every collection on disk
causalmesh verify --run path/to/a/run_dir   # one exported run, anywhere
```

The last form is the one that matters for an audit: it needs no checkout, no
index and no relay — just the directory. That is the clean-room check (§82).

A tampered chain is refused with the mismatch named, rather than reported as
a warning:

```
run: recorded digest d33b3d27... does not match recomputed 856b7e95...;
the event content changed
```

### The same thing from Python

```python title="verify.py"
import json
from pathlib import Path

from causalmesh.crypto.keys import KeyPair, PublicKeyRing
from causalmesh.experiments import derive_run_seed
from causalmesh.verifier import verify_chain

SEED = b"a-seed-you-record-somewhere"

for directory in Path("data/raw/my_first_run").iterdir():
    if not directory.is_dir():
        continue
    payload = json.loads((directory / "run.json").read_text(encoding="utf-8"))
    chain = payload["chain"]

    run_seed = derive_run_seed(SEED, payload["run_id"])
    actors = {r["event"]["identity"]["agent_id"] for r in chain}
    ring = PublicKeyRing.from_keypairs(
        {a: KeyPair.derive(run_seed, a) for a in actors}
    )

    report = verify_chain(chain, ring)
    print(payload["arm"], report.valid, report.summary())
```

The verifier imports nothing from the relay — that boundary is enforced by a
test — so this works on a different machine, months later, with the system
shut down.
