# frontend

The CausalMesh website: one Next.js app serving both the landing page and the
documentation. The whole site lives here — `/` is the landing page and `/docs`
is the documentation, from the same app.

| Route                     | Description                                          |
| ------------------------- | ---------------------------------------------------- |
| `app/page.tsx`            | Landing page, composed from `components/landing/`.    |
| `app/docs/[[...slug]]`    | Documentation pages, rendered from `content/docs/`.   |
| `app/docs/layout.tsx`     | The Fumadocs docs layout (sidebar, search, TOC).      |
| `app/api/search/route.ts` | The Route Handler for search.                         |
| `app/layout.tsx`          | Root layout: fonts and shared metadata.               |

Run the development server from the repository root:

```bash
npm install
npm run dev     # http://localhost:3000 — landing at /, docs at /docs
npm run build
```

## Structure

- `content/docs/` — the MDX source for every documentation page. Internal
  links are written with the `/docs` prefix, because the docs are mounted at
  `/docs` rather than at the root.
- `components/marketing/` — the landing page, one component per section, in
  page order: `Hero`, `Architecture`, `SystemSections` (01 to 05),
  `ClosingSections` (developer, measured, research, FAQ, CTA).
- `components/system/` — the technical surfaces the sections are built from:
  `ArchitectureDiagram`, `VerdictConsole`, `ToolRegistry`, `ClaimReplay`,
  `EntrySurfaces`, `ExecutionTrace`, `BenchmarkTable`, `CodeBlock`, `Panel`.
- `components/ui/` and `components/layout/` — primitives (`Section`,
  `Reveal`, `TrackedLink`) and the shared chrome (`SiteNav`, `SiteFooter`,
  `BrandMark`).
- `components/landing/` — the whitepaper (`Paper.jsx`) and its icons, still
  on the landing palette tokens; `app/site.css` re-tones it for the stage.
- `lib/site/content.ts` — every fact the landing page states, with its
  source. Verdicts are real `causalmesh policy check` output, the trace is
  a real run's signed chain.
- `lib/landing/` — `results.json` is generated by `scripts/export_results.py`
  from real run artifacts; do not hand-edit it.
- `lib/analytics.ts` — vendor-free intent events (`site:track` DOM event and
  `window.dataLayer` when present).
- `app/site.css` — the site design system: tokens, the 1487 x 1058 hero unit
  system, fades, motion, the mobile menu. `app/landing.css` holds the older
  palette the whitepaper is written against.
- `lib/source.ts` — the content source adapter. `lib/layout.shared.tsx` holds
  shared layout options.
